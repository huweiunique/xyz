# 测试范围与运行方式

## 默认后端检查

```bash
python tests/run_all.py
python tools/apply_local_patches.py --check
```

默认运行静态检查、后端离线测试及不依赖浏览器的脚本测试，不启动 Chrome/Edge。浏览器测试类明确显示为跳过，不计为已通过；macOS 原生测试仍按平台条件运行。

Backend tests 使用这一默认范围，然后执行补丁检查、Docker 构建及容器健康检查。在线测试仍由 `--online` 控制，与 UI 开关独立。

## 可选浏览器自动测试

```bash
python tests/run_all.py --ui
```

仅在用户明确要求时运行该选项，日常验证和 CI 均不自动启用。该选项额外运行播放器布局、播放行为、控制层、优选 IP 界面和沉浸观看的 Chromium 自动测试，需要本机 Chrome/Edge。这些用例保留，未删除或降低断言；Linux 无头环境的输入能力模拟问题仍可能导致桌面导航用例失败，默认后端检查通过不代表这些用例已修复。

定向运行单个浏览器用例时，可设置 `HGHUB_UI_TESTS=1` 后使用 unittest；`run_all.py` 始终以 `--ui` 参数为准，不继承此环境变量的启用状态。

UI 改动继续遵守 AGENTS.md：启动独立端口的实际 Web 与代理，在真实浏览器中验证受影响的页面与操作，记录证据并清理本次进程。可选自动测试不能替代实际页面验证。

## iOS 原生转发检查

在 macOS 上执行 `python3 tests/test_prefip_transport.py -v`，测试直接编译 `PreferredIP.swift` 中的实际 `CFConnectProxy`，连接本机 TCP 回环服务，不依赖上游、Cloudflare 或视频内容。Windows/Linux 会明确跳过，不能把跳过算作原生验证通过。Nightly 的 IPA 任务在打包前运行这项检查及候选 IP 择优检查，失败即停止打包。

转发回归覆盖：原有 76,800 字节数据及 12 字节尾部、空数据、16 KiB 和 64 KiB 前后边界、关闭写端前的分段即时收发、精确域名与端口限制、允许和禁止回退。断言逐字节比较完整内容，没有用缩小测试数据或放宽长度绕过截断。

已建连后的连接失败状态不能直接取消双向通道：状态通知可能先于尾部数据的收发完成回调。通道须先处理接收回调附带的数据，由每个方向分别完成数据发送及写端关闭，再统一释放资源；对端未结束时仍保留原有 15 秒收尾上限。

2026-11-15 在 GitHub macOS runner 上完成本次修复验证：5 项原生转发测试全部通过，随后在无临时诊断注入的同一实现上重复原失败场景 20 次，全部逐字节一致。运行记录：[原生转发回归与重复验证](https://github.com/huweiunique/xyz/actions/runs/43615075973)。这证明测试通道的收尾完整性，iPhone 真机连接仍需安装产物后验收。

Windows 本地默认检查为 111 项：90 通过、21 跳过、0 失败、0 错误，另有 6 个浏览器测试类按默认开关整体跳过。macOS 专属项在 Windows 跳过，与上述真实 macOS 验证分开报告。
