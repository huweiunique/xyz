# 上游地址变化盘点与自动适配

2026-11-17 核查范围：`proxy/`、Web 服务与页面、本地扩展、Android 原生及随包页面、
iOS 原生、补丁工具、Docker 与 CI。排除第三方压缩版 hls.js 内部实现、示例地址、
许可证链接和测试样本，不把同一份规则的多个入口重复计算。

## 结论与处理范围

真正因资源域名变化而拦截的规则共 **2 组**，覆盖 **5 个 HTTP 入口**。
另有 **1 处 API 上游配置不一致**，本次一并修复。

| 类别 | 位置或入口 | 处理结果 |
| --- | --- | --- |
| 封面白名单 | `web/server.py` 的 `/proxy/img` | 前一提交已从可信内容响应登记完整封面 URL；本次复用其网络下载边界并回归验证 |
| 播放白名单 | `proxy/server.py` 的 `/proxy`、`/proxy/m3u8`、`/proxy/key`、`/proxy/ts` | 四个入口统一交给 `local_ext/media_proxy.py`，登记清单、子清单、密钥、分片及初始化资源 |
| API 入口配置 | Web 原有 `UPSTREAM` 环境变量，播放服务原先写死域名 | 两个服务现在共用 `UPSTREAM`，Compose 透传；CI 在线预检也读取同一变量 |
| Android / iOS 原生壳 | CDN 域名判断与优选 IP 拦截 | 未发现额外的上游 CDN 固定白名单；Android 按构建配置的后端 host 判断优选，iOS 按用户配置的后端 URL 工作 |
| Web / Android 随包页面 | `UP` 声明、封面函数与播放地址 | `UP` 仅为未使用的声明；内容 API 已走同源，图片地址与播放地址来自接口，无第二套有效的 CDN 白名单 |

还发现以下固定外部地址，它们属于独立功能入口，不是从上游播放响应获得的资源，
因此不进入自动登记，也没有在本次擅自更换目标：

| 固定地址 | 实际用途与边界 |
| --- | --- |
| `sp1.45678.eu.org` | 页面分享链接目标，在 Web 与 Android 页面各有一份；未在本次验证其可用性 |
| 上游 GitHub `v1.2.0.8` APK URL | 页面下载按钮，在 Web 与 Android 页面各有一份；不是当前仓库 Nightly，也不属于 CDN 访问规则 |
| `cf.090227.xyz` | 优选 IP 列表，Python 扩展与 Android、iOS 各有调用，另有已被扩展接管的旧 Web 实现；不是播放/封面地址发现渠道 |
| jsDelivr hls.js 地址 | Web 与 Android 页面在本地 hls.js 加载失败时的备用地址；常态使用本地脚本 |

可信 API 入口整体更换时，须由运营者配置 `UPSTREAM=https://新入口` 并重新创建服务；
不会从客户端或陌生页面自动学习新的 API 信任源。应用自身的后端地址仍由用户配置。

## 播放资源何时登记

1. 固定上游的播放接口成功返回后，服务端先登记 `streams` 中所有有效的 HTTPS URL，
   包括当前 `main`、`hevc`、`preview`，再把原始播放响应交给客户端。
2. 客户端选择代理线路，请求已登记的清单。
3. 服务端下载并验证 `#EXTM3U`，按原始清单 URL 解析相对引用，登记子清单、密钥和分片。
4. 先完成资源登记，再将引用重写为同源 `/proxy/m3u8`、`/proxy/key`、`/proxy/ts` 地址返回。
5. 子清单请求重复上述过程；不存在“页面出现一个地址就整域名放行”的路径。

普通 URI 行、`EXT-X-STREAM-INF` 后的子清单、`EXT-X-MEDIA`、`EXT-X-I-FRAME-STREAM-INF`、
`EXT-X-KEY`、`EXT-X-SESSION-KEY`、`EXT-X-MAP` 等 URI 属性均纳入登记。
相对 URI 按 [RFC 8216 第 4.1 节](https://www.rfc-editor.org/rfc/rfc8216.html#section-4.1)
相对于其所在清单解析，不用代理地址作为上游基址。

直连线路仍由客户端访问上游资源；代理线路现在把清单中的上述资源统一送回后端，
后端流量随之增加。应用现有说明里的“后端代取清单”应按这一扩展后的服务端行为理解。
本次没有更改页面、原生代码或随包资源，不需要重编 APK、IPA。

## 访问边界与错误定位

- 播放资源仅按完整 URL 登记，不再依赖旧域名或域名后缀；同域名的陌生路径仍拒绝。
- 仅 HTTPS 默认端口、无 URL 用户信息与片段；DNS 全部结果须为公网单播地址。
  与封面共用固定 IP 连接、TLS 原域名校验、禁重定向的下载器。
- 每个播放进程最多 50,000 条登记，一小时有效。子资源继承播放根记录的截止时间，
  不因反复请求而无限延长；重启、到期或容量淘汰后必须重新获取播放接口。
  多实例部署应保证同一次播放的接口及资源落在同一播放进程。
- 清单最多 2 MiB、单份清单最多 10,000 条引用；密钥最多 64 KiB、单个分片最多 64 MiB。
  下载使用 30 秒 socket 超时，无大型视频分片内存缓存，收到完整资源后返回。
- CDN 鉴权仅采纳播放响应中的 `x-cdn-auth`，在服务端内存中向子资源继承；
  客户端伪造的同名头不能覆盖。鉴权值不写入清单 URL，不写入新增诊断日志。
- 未登记返回 403、`source=local_policy`；上游 403 返回 403、`source=upstream`；
  公网校验、下载或清单解析失败返回 502、`source=resource_validation`。
  上游 3xx 不透传为浏览器跳转。

这解决的是资源地址轮换。API 字段、解密协议、DRM、特殊 URI 协议、HTTP/非默认端口、
特殊清单扩展、Range/低延迟流式协议等变化不保证自动兼容，仍须按实际协议适配。
