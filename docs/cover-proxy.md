# 封面图床自动适配

封面完整 URL 由上游内容 API 的 `cover` 字段返回。2026-11-17 实测图床已切换到
`pic.qnlycc.cn`，旧服务端固定白名单使 `/proxy/img` 返回 403；现有 AES-128-CBC
无填充参数仍可解密。此次通过 `local_ext/cover_proxy.py` 和受控补丁修复，不修改上游正文。

## 自动适配范围

服务端在转发成功的上游内容 GET 响应时，登记 `data` 中的完整封面 URL：

- `/api/videos`、`/api/videos/:id`：列表、分类与详情。
- `/api/search`、`/api/ranks/:type`、`/api/posts`、`/api/posts/:id`。
- `/api/up/*` 别名经转换后使用同一流程。

每个进程最多登记 10,000 个 URL，有效期一小时；客户端不能通过图片请求自行登记地址。
未来更换图床，只要仍由上述内容接口返回 HTTPS 封面，刷新对应页面即可自动适配。
只登记完整 URL，不对同域名的其他路径和签名放行。现有白名单及 `pic.qnlycc.cn` 保持兼容。

登记保存在内存中。重启或一小时后，从浏览历史直接打开未登记的新图床封面可能返回 403；
重新加载列表、搜索或详情即可重新登记。多实例部署须保证图片与内容请求落到同一实例，
或用下述显式域名配置兼容。上游接口、字段或解密协议变化仍需单独适配。

## 手动兼容与错误处理

可用 `HGHUB_IMAGE_HOSTS=pic.example.com,other.example.com` 增补图床域名，
不填协议、路径、端口或通配符。Compose 已透传该变量；修改配置后须重新创建服务才生效。
单独运行容器时以 `-e HGHUB_IMAGE_HOSTS=...` 传入。

图片仅允许 HTTPS 默认端口，拒绝 URL 用户信息和片段，DNS 全部结果均须为公网单播地址。
连接固定到已校验的 IP，TLS 仍校验原域名；不跟随重定向，响应最多 8 MiB，连接超时 20 秒。
上游图片非 200、下载异常、无法解密或格式无法识别均返回 502，不缓存失败内容。
成功 JPEG、PNG、WebP、GIF 最多缓存 200 张；不会再把密文伪装成 JPEG。

解密优先使用 `HGHUB_OPENSSL` 指定路径，其次 PATH 中的 `openssl`，Windows 再尝试
系统级或用户级 Git 自带的 OpenSSL。容器继续使用已安装的系统 OpenSSL，无 pip 依赖。
密钥和 IV 仍沿用现有上游公开参数，本次未引入自动更新密钥。
